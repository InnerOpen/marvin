# Glossary

One line per term. Links go to the page that covers it.

- **Agent** — a workspace-defined or built-in (`marvin`, `ask`, `chat`) AI actor with a kind (`persona` runs tools, `model` is plain completion), a system prompt, a minimum role and a tool policy; run with `POST /api/ai/agents/{slug}/run`. The built-in `marvin` is the router: it can hand a request off to another agent, and it is listed under the workspace's assistant name. See [Agents and Ask](whats-new/agents-and-ask.md).
- **AI limits (budget)** — a workspace's monthly cost limit, daily request limit and per-request output-token cap (`budget_config`), shown against this month's usage on **AI Settings → Usage & Limits**; at a limit new AI runs are refused, and crossing `AI_BUDGET_WARNING_PERCENT` of the monthly limit raises a toast. See [Agents and Ask](whats-new/agents-and-ask.md#usage-and-limits).
- **API client (`marvin_sk_`)** — a per-workspace credential with a permissions map (`read:published_entries`, …) used by sites and `marvin-mcp` against the publishing API; managed under **Settings → Publishing → Site Clients** (`/publishing/clients`). See [Auth and tokens](auth-and-tokens.md).
- **Ask thread** — a server-side conversation with an agent (`/api/ai/threads`); runs with `thread_id: "new"` open one, later turns continue it. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Asset** — an uploaded file stored by the `local` or `s3` provider and attachable to entries; served to sites at `/api/publish/{workspace_slug}/assets`. See [Operations → Storage](operations.md#storage).
- **Automation** — see *Workflow*.
- **Approval mode** — the workspace AI setting that decides whether AI-generated content is written back directly or only suggested; it covers every AI write-back, while what an agent may do itself is its tool policy. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Blueprint** — a declaration of a `collection`, `entry_type`, `entry_fields`, `scheduled_task`, `event_subscription`, `incoming_webhook` or `workflow` a workspace could have; applying (ADMIN or OWNER) creates only what is missing and never overwrites, webhooks and workflows arrive switched off, and an applied workflow can be updated to its integration's current version. See [Blueprints](whats-new/blueprints.md).
- **Bubble character** — an animated character the Ask bubble shows instead of its icon, one GIF, WebP or PNG animation per state (idle, idle fidget, greeting, thinking, working, waiting for approval, success, error, dragging left and right); file names pick the states, missing states fall back to idle. Set under **AI Settings → Persona** for the workspace and on **Agents** (**Edit → Bubble character**, or the card's **Character** button) for a custom agent, which the bubble shows while that agent talks. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Bubble lines** — the Ask bubble's canned greetings, taglines, working lines, error openers and emotes. A workspace with its own Character gets a set written in that character's voice by one AI call when the Character is saved, editable under **AI Settings → Persona → Bubble lines**; otherwise Marvin's lines while the assistant is named Marvin, and a neutral set for a renamed assistant. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Character library** — bubble-character packs a platform super admin installs under **Admin → Extensions → Character Library** (`/api/admin/character-packs`) for any workspace or agent to pick; their files belong to no workspace, and deleting a pack in use first asks, then moves its users back to their icon (or, for an agent, the workspace's character). See [Agents and Ask](whats-new/agents-and-ask.md).
- **Collection / smart collection** — a manual list of entries, or one whose membership is derived from rules (`entry_types`, `statuses`, `published_within_days`, `created_within_days`, `match: all|any`) and reconciled nightly by `resync_smart_collections`. See [Collections](whats-new/collections.md).
- **Connection** — a configured instance of an integration provider in a workspace (credentials, config), listed under **Settings → Integrations**. See [Integrations](whats-new/integrations.md).
- **Entry** — a content item of one entry type with `data` fields, metadata and a status. See [Home](index.md).
- **Entry type** — a field schema plus capabilities (for example `submission` for forms); entries are instances of it. See [Home](index.md).
- **Error policy** — what a provider declares should happen when one of its actions fails, code by code: send the entry to review (a published entry stays published), retry later and resume at the failed step, alert admins, or carry on. Core applies it to every workflow using the integration; admins adjust **Review** / **Alert** per connection on the card's **How errors are handled** table, and a workflow opts out with on-failure steps or `integration_errors: "fail"`. See [Integrations](whats-new/integrations.md#when-an-integration-fails).
- **Event / event log** — an internal notification with a snake_case name (for example `entry_created`, `entry_published`, `form_submission_received`, `automation_ran`) that can fire webhooks and workflows; the log is pruned by `EVENT_LOG_RETENTION_DAYS`. See [Workflows](whats-new/workflows.md).
- **Event subscription** — a rule that sends a workspace event to an integration action; can be created from a blueprint. See [Integrations](whats-new/integrations.md).
- **Form (submittable entry type)** — an entry type with submission capabilities; a public `POST /api/publish/{workspace_slug}/forms/{slug}/submit` creates an `inbox` entry. See [Forms and submission protection](whats-new/forms-and-submission-protection.md).
- **Handler** — the code a scheduled task runs, named by `task_type` (for example `publish_scheduled_entries`, `run_automation`, `run_integration_action`, `prune_event_logs`). See [Scheduled tasks](whats-new/scheduled-tasks.md).
- **Incoming webhook** — a tokenised endpoint `POST /api/hooks/{token}` that turns an outside request into a workflow trigger, optionally verified with a core, integration-provided or custom signature scheme (an HMAC, or a static token in a header) using the secret named by `signing_secret_ref`. See [Incoming webhooks](whats-new/incoming-webhooks.md).
- **Integration alert** — one open alert per connection and error code that marks the card **Needs attention** (with **Test** and **Resolve**), goes to the bell and to the channels set under Settings → Automation → **Notifications** (the *Integration needs attention* kind), reminds while open, and announces when the connection works again through the same channels. Open and resolved alerts are listed on the Alerts & health page. See [Integrations](whats-new/integrations.md#integration-alerts).
- **Integration / provider** — an installable plugin (Slack, Instagram, Apprise, Square, n8n, …) that declares credentials, actions, emitted events and content; a provider becomes usable once a connection exists, and a workflow's `integration` step can run its actions. See [Integrations](whats-new/integrations.md).
- **Invocation source** — where an AI request comes from (`editor`, `bubble`, `ask_page`, `automation`, `mcp`, `api`, and `agent` for agent chat from the API, which follows the two Ask toggles); the workspace can switch sources off. It is feature gating, not a security boundary. See [Agents and Ask](whats-new/agents-and-ask.md).
- **MCP server (external)** — a Model Context Protocol server a workspace registers under **Settings → MCP servers** (`/api/ai/mcp-servers`) so agents can call its tools. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Marvin as MCP server** — the `marvin-mcp` package, which exposes a workspace's content and operations as MCP tools using an API client token. See [Marvin as an MCP server](whats-new/marvin-as-mcp-server.md).
- **Media embed** — a player for a supported media link (YouTube, Vimeo, Spotify, SoundCloud, Apple Music/Podcasts, TIDAL, Simplecast, Transistor, Bandcamp embed code): a link alone on its own line in a markdown field, or an `embed` field. Published under an entry's `embeds`, keyed by the link as written, with Marvin-built `html` in the site's privacy mode (`site.embeds.mode`: `click_to_load` or `direct`). See [Media embeds](whats-new/media-embeds.md).
- **Notifications** — Settings → Automation → Notifications: which of a workspace's failures (a workflow, a scheduled task, a connection that needs attention; AI operations and webhook deliveries if switched on) go past the bell by email or chat, once per incident with a "working again" note. The workspace counterpart of platform alerts; platform events never go there. See [Notifications](whats-new/notifications.md).
- **Operation (AI)** — a named AI task with a slug: `generate-summary`, `generate-tags`, `improve-writing`, `generate-alt-text`, `classify-form-submission`, `describe-image`, `enrich-resource-metadata`, `answer-workspace-question`; runnable directly, from a workflow step or by an agent. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Personal API token (`marvin_tk_`)** — a long-lived token that acts as its owner with no scopes, limited only by workspace role; managed under **Profile → Manage Tokens** (`/user/api-tokens`). See [Auth and tokens](auth-and-tokens.md).
- **Platform workspace** — the admin's workspace, the one platform alerts and shared services run from; marked `is_platform` and found by that marker, so a super admin can rename it (name and slug, old slug kept as an alias) but not delete it. Badged **Admin** for super admins. See [Operations → Platform workspace](operations.md#platform-workspace).
- **Plugin** — a Python package the platform operator installs into the backend (image or Helm init container) that registers providers; today every plugin is an integration plugin. Super admins see them under **Admin → Extensions → Plugins**; each workspace then connects the providers it wants as integrations. See [Integrations](whats-new/integrations.md).
- **Publishing API** — the read side for sites, `GET /api/publish/{workspace_slug}/{entries|collections|assets|resources|entry-types|site}`, authenticated with an API client. See [Publishing API](whats-new/publishing-api.md).
- **Resource** — an external link or reference record attachable to entries; published at `/api/publish/{workspace_slug}/resources`. See [Home](index.md).
- **Role (workspace)** — a member's rank in one workspace: `VIEWER` reads, `AUTHOR` creates entries and edits their own until approved or published, `EDITOR` manages all content and has the AI write tools, `ADMIN` adds workspace settings, members, entry types and forms, `OWNER` everything. Platform super admins pass every check. See [Auth and tokens](auth-and-tokens.md#roles).
- **Scheduled task** — a stored task with a handler, a schedule (`interval` or `once`; cron is not wired) and a config, fired by the scheduler tick. See [Scheduled tasks](whats-new/scheduled-tasks.md).
- **Search index** — the embeddings `search_content` and grounded Ask answers read: published entries, resources and assets, kept current as content changes and rebuilt in the background by **Reindex now** or the `ai_reindex_embeddings` task. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Secret / variable** — workspace values referenced as `{{SLUG}}` and managed under **Settings → General → Environment**; secret values are never listed, only workspace admins may set, change, delete or reveal one, and they are stored by `SECRET_BACKEND`; variables are readable. See [Auth and tokens](auth-and-tokens.md#secrets-and-variables).
- **Site rebuild** — a request to rebuild a static site, queued per workspace and sent as `webhook_triggered` to the deploy hook once edits go quiet, carrying the request count and the changes it covers (listed in the **Site rebuild** toast); `request_site_rebuild` and, unless **Rebuild the site automatically** is off, published content changes queue one. The rebuild being sent shows as **Site Rebuild Sent** on the Events page. A host can report the result back as `site_deployment_*` events (`site_build_*` are their old names). See [Publishing API](whats-new/publishing-api.md#site-rebuilds).
- **Status lifecycle** — an entry's status is one of `inbox`, `processing`, `draft`, `needs_review`, `approved`, `published`, `archived`, `trashed`; new entries start in `inbox` and the review queue lists `needs_review` and `approved`. See [Home](index.md).
- **Submission protection** — platform defaults with per-workspace overrides for public submits: review or reject mode, domain lists, exempt IPs, client capture, surge detection. See [Forms and submission protection](whats-new/forms-and-submission-protection.md).
- **Tag** — a workspace label attachable to entries and resources (`/api/platform/tags`); `generate-tags` can create them. See [Home](index.md).
- **Tool policy** — an agent's map of tool category or tool name to `allow`, `block` or `ask` (Ask first), resolved allowlist → tool → category → default. Ask first pauses the run on its Ask thread until the user approves; where there is no thread the tool is not offered. A write is never allowed to a caller below EDITOR. See [Agents and Ask](whats-new/agents-and-ask.md).
- **Trash** — where a deleted entry (status `trashed`), asset or resource (`trashed_at` set; an asset keeps its file) waits, out of every list but the Trash collection's tabs, until it is restored or deleted forever; emptied by a workspace admin or automatically after the workspace's limit. See [Trash](whats-new/trash.md).
- **Webhook (outgoing)** — a stored HTTP target of type `generic`, `user`, `entries`, `event_driven` or `workflow`, delivered by the scheduler tick with a delivery log. See [Outgoing webhooks](whats-new/outgoing-webhooks.md).
- **Workflow (automation)** — a definition with a trigger (`event`, `manual`, `schedule`, `chained`, `on_error`, `incoming_webhook`, `mcp`), conditions and steps (`operation`, `entry`, `emit_event`, `handler`, `webhook`, `integration`), stored under `/api/automations`; a `target` query can run the steps once per matching entry. See [Workflows](whats-new/workflows.md).
- **Workspace (group)** — the unit of isolation: content, members with roles, settings, secrets, API clients and automation all belong to one workspace; the API and database call it a group (`group_id`). See [Home](index.md).
